# CONTEXTO DEL PROYECTO

Estoy desarrollando un proyecto universitario para el curso "Tópicos en Tecnologías Inmersivas".

El proyecto consiste en desarrollar una aplicación móvil Android que utilice Realidad Aumentada (AR) para identificar componentes de una computadora mediante la cámara y proporcionar información y una guía visual para su ensamblaje y desensamblaje.

El objetivo principal es desarrollar un prototipo funcional de aprendizaje y asistencia para hardware de computadoras.

==================================================
OBJETIVO DEL PROYECTO
==================================================

La aplicación debe permitir que un usuario apunte la cámara de su teléfono hacia un componente físico de computadora.

La aplicación debe:

1. Reconocer el componente.
2. Identificar qué componente es.
3. Mostrar información técnica del componente.
4. Permitir seleccionar "Ensamblar" o "Desensamblar".
5. Mostrar una guía paso a paso utilizando Realidad Aumentada.
6. Mostrar flechas, indicadores, textos, resaltados y/o modelos 3D para explicar cada paso.
7. Permitir avanzar y retroceder entre los pasos.
8. Mostrar advertencias y recomendaciones de seguridad cuando corresponda.

El sistema NO debe intentar inicialmente reconocer cualquier componente existente en el mercado.

El reconocimiento estará limitado a un conjunto pequeño de componentes.

==================================================
COMPONENTES INICIALES
==================================================

Para el MVP se trabajará inicialmente con:

- Memoria RAM
- SSD
- CPU
- GPU

Sin embargo, el desarrollo inicial debe comenzar solamente con:

1. RAM

Una vez que el flujo completo funcione correctamente con RAM, se incorporarán los demás componentes.

==================================================
FLUJO PRINCIPAL
==================================================

El flujo esperado de la aplicación es:

INICIO
  ↓
ESCANEAR COMPONENTE
  ↓
CÁMARA
  ↓
RECONOCIMIENTO VISUAL
  ↓
COMPONENTE IDENTIFICADO
  ↓
PANTALLA DE INFORMACIÓN
  ↓
[ INFORMACIÓN ]
[ ENSAMBLAR ]
[ DESENSAMBLAR ]
  ↓
GUÍA AR
  ↓
PASOS INTERACTIVOS
  ↓
FINALIZACIÓN

Ejemplo:

El usuario apunta la cámara hacia una memoria RAM.

El sistema identifica:

"Memoria RAM"

Luego muestra:

--------------------------------
MEMORIA RAM
--------------------------------

Tipo: DDR4
Función: Memoria de acceso aleatorio
Capacidad: 8 GB
Velocidad: 3200 MHz

[ Ver información ]
[ Ensamblar ]
[ Desensamblar ]

Si selecciona "Ensamblar":

Paso 1:
"Identifique la ranura DIMM de la placa madre."

La aplicación debe mostrar visualmente la ubicación de la ranura.

Paso 2:
"Abra los seguros laterales de la ranura."

Paso 3:
"Alinee la muesca de la memoria RAM con la ranura."

Paso 4:
"Inserte la memoria verticalmente hasta asegurarla."

Paso 5:
"Verifique que los seguros laterales estén cerrados."

Al finalizar:

"Instalación completada."

El procedimiento de desensamblaje tendrá sus propios pasos.

==================================================
REALIDAD AUMENTADA
==================================================

Utilizar AR Foundation como capa principal de realidad aumentada.

Utilizar ARCore XR Plugin para Android.

La aplicación debe utilizar inicialmente:

- AR Camera
- AR Session
- AR Session Origin / XR Origin según la arquitectura disponible en Unity 6
- Plane detection si es necesario
- Raycast
- Tracking espacial
- Anchors si son necesarios

No agregar funcionalidades AR innecesarias inicialmente.

El objetivo es conseguir primero una escena AR básica funcionando correctamente en un dispositivo Android.

==================================================
RECONOCIMIENTO DEL COMPONENTE
==================================================

La aplicación debe utilizar reconocimiento visual para identificar componentes.

Sin embargo, el sistema debe diseñarse de forma modular para que el reconocimiento pueda cambiarse posteriormente sin modificar el resto de la aplicación.

La arquitectura deseada es:

Camera
  ↓
Recognition Service
  ↓
Component ID
  ↓
Component Repository
  ↓
Component Information
  ↓
AR Guide

Por ejemplo:

Recognition Service
  ↓
"RAM"
  ↓
ComponentRepository
  ↓
RamComponent
  ↓
AssemblyProcedure
  ↓
AR Guide

NO acoplar directamente el modelo de IA con la interfaz.

==================================================
ESTRATEGIA DE DESARROLLO DEL RECONOCIMIENTO
==================================================

No quiero comenzar entrenando una IA compleja.

Primero debe implementarse un reconocimiento simulado/manual para poder desarrollar el resto del sistema.

Por ejemplo:

Botón:

"Simular reconocimiento RAM"

Esto debe comportarse como si el modelo de IA hubiera identificado una RAM.

Esto permitirá desarrollar:

- Información
- UI
- procedimientos
- AR
- modelos 3D
- navegación

Posteriormente se reemplazará el reconocimiento simulado por un modelo real de visión artificial.

La arquitectura debe permitir cambiar:

MockRecognitionService

por:

AIRecognitionService

sin modificar el resto de la aplicación.

==================================================
IA / VISIÓN ARTIFICIAL
==================================================

La integración de IA debe realizarse posteriormente.

La IA tendrá una única responsabilidad inicial:

Identificar el tipo de componente observado.

Ejemplo de salida:

{
    "component": "RAM",
    "confidence": 0.94
}

O:

{
    "component": "GPU",
    "confidence": 0.91
}

Si la confianza es demasiado baja:

"Componente no identificado. Intente acercarse o mejorar la iluminación."

No es necesario reconocer marcas o modelos específicos.

Por ejemplo:

Correcto:
"RAM"

No necesario:
"Kingston Fury Beast DDR4 3200 8GB"

==================================================
DATOS DE COMPONENTES
==================================================

Los componentes deben diseñarse utilizando datos independientes del código.

Inicialmente puede utilizarse JSON o ScriptableObjects.

Cada componente debe tener:

- id
- nombre
- descripción
- función
- características
- advertencias
- modelo 3D
- pasos de ensamblaje
- pasos de desensamblaje

Ejemplo conceptual:

{
    "id": "ram",
    "name": "Memoria RAM",
    "description": "...",
    "function": "...",
    "specifications": [],
    "warnings": [],
    "assemblySteps": [],
    "disassemblySteps": []
}

Preferir una arquitectura que permita agregar nuevos componentes sin modificar la lógica principal.

==================================================
GUÍA DE ENSAMBLAJE
==================================================

La guía debe ser genérica y reutilizable.

Debe existir un sistema como:

AssemblyGuideController

que reciba un componente y sus pasos.

Cada paso debería contener:

- título
- descripción
- número de paso
- imagen opcional
- modelo/animación opcional
- posición AR
- indicador visual
- advertencia opcional

Ejemplo:

Step 1
Título:
"Identificar ranura DIMM"

Descripción:
"Localice la ranura correspondiente en la placa madre."

AR:
Resaltar zona de la ranura.

Step 2
Título:
"Alinear RAM"

Descripción:
"Alinee la muesca de la RAM con la ranura."

AR:
Mostrar flecha.

==================================================
GUÍA DE DESENSAMBLAJE
==================================================

Debe utilizar la misma arquitectura que ensamblaje, pero con pasos diferentes.

Ejemplo RAM:

1. Apagar el equipo.
2. Desconectar la alimentación.
3. Identificar la memoria.
4. Liberar los seguros laterales.
5. Retirar la memoria sujetándola por los bordes.

==================================================
MODELOS 3D
==================================================

Los modelos 3D se crearán o editarán mediante Blender.

Inicialmente no es necesario crear modelos extremadamente detallados.

Se pueden utilizar modelos simplificados pero visualmente claros.

Modelos iniciales:

- RAM
- Motherboard
- SSD
- CPU
- GPU

La aplicación debe utilizar Prefabs de Unity para los modelos 3D.

Los modelos deben poder reutilizarse en:

- información
- ensamblaje
- desensamblaje
- animaciones
